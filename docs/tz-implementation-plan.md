## Overview

Прототип уже проверяет комплект «запрос → КП → ТЗ»: хронология, номенклатура, полнота пакета, часть лингвистических правил, отчёт, решение оператора и eval. Страницы «Поставщики», «Расчёты», «ОКПД2», «Календарь» и «Обеспечение» считают локально и в граф не входят.

Дальше система доводится до функций 4.2 тем же способом, что и текущее ядро:

- правило считает детерминированный код;
- недостающее значение получает статус «требует уточнения» или «не проверен», без подстановки;
- LLM остаётся необязательным proposer и не повышает статусы;
- внешний реестр вызывается только через выключенный по умолчанию адаптер;
- каждый спринт оставляет `pytest` и Streamlit-прогон рабочими.

Итоговый артефакт спринтов 1–6 — сводное заключение по 8 блокам п. 4.2.4. Спринты 7–14 закрывают календарь процедуры, легитимность, рыночную цену, заявки участников, протоколы, договор и конструктор запросов. Спринт 15 — локальный отчёт о соответствии. Спринты 16–20 — поиск характеристик по п. 4.2.10.1.2: 16–19 на фиктивном клиенте, 20 — живой HTTP по allowlist и только после отдельного подтверждения.

## Принятые решения

- Ближайший объём — весь план, спринты 1–14, до конструктора запроса включительно.
- Справочники ОКПД2/СМП, перечень ПП РФ № 1875 и производственный календарь кладутся как примеры формата. Нет боевого файла — проверка ставит «не проверен» и не подставляет значения.
- Хронология комплекта остаётся на странице «Календарь». Сроки процедуры из п. 4.2.7 считаются на отдельной странице.
- 2026-11-11, п. 4.2.10.1.2: поиск характеристик не входит в прогон комплекта. Спринты 16–19 работают на фиктивном клиенте и сеть не вызывают. Живой HTTP — спринт 20, флаг `KP_CHARACTERISTIC_SEARCH` выключен по умолчанию, запросы только к хостам allowlist. Общий поисковик, маркетплейсы, ЕИС, ЭДО, КонсультантПлюс и Гарант не входят. Выгрузки PDF, DOCX и XLSX отложены. Найденная строка остаётся кандидатом, пока оператор её не примет. Процент и класс отклонения до этого не считаются. Цифры ТЗ «80% параметров», «95% точности» и «поиск до 5 минут» — цель приёмки живого этапа, не заявление прототипа.

## Общие правила для всех спринтов

- Статус пары `FinalStatus` можно только понизить. Новый блок не переводит «Не соответствует» в «Соответствует».
- Число считается дважды независимыми функциями, если ТЗ требует двойного счёта. Расхождение двух результатов — «требует ручной проверки» и оба значения в отчёте.
- Деньги в отчёте: два знака, разряд — пробел, дробь — запятая (`12 450,00`).
- Для каждого ключевого числа хранится источник: файл, позиция, фрагмент текста.
- Несколько версий одного документа фиксируются риском. Версия не выбирается автоматически.
- Внутреннее противоречие документа хранится отдельно от расхождения между документами.

## Testing Strategy

- Каждый спринт добавляет узкий файл `tests/test_*.py` и не ослабляет `tests/test_eval.py`.
- Golden для блоков хранится отдельно от golden пар: `tests/eval/blocks_golden.json` появляется в спринте 6, когда итог стабилен.
- Фикстуры документов — короткие docx, созданные в тесте через `python-docx`, без секретов реальных поставщиков.
- Перед сдачей спринта: `PYTHONPATH=src .venv/bin/python -m pytest -q`.
- UI-спринты 1, 3, 5, 6, 7, 13 и 19 проверяются в браузере: прогон со страницы «Проверка», переход по затронутым страницам, пустой комплект, комплект без нового типа файла.
- Сетевые тесты не ходят в интернет. Адаптер подменяется фиктивным объектом. Спринт 20 проверяет транспорт заглушкой.

## Potential Risks & Gotchas

- Делитель CV уже зафиксирован как деление на n в `calculations.py`. Менять его можно только после сверки с текстом Приложения № 3 и с обновлением тестов. Второй алгоритм спринта 3 обязан повторять тот же делитель.
- Страницы 6–10 сейчас парсят `incoming` сами. До конца спринта 1 легко получить два разных статуса. Спринт 1 снимает второй путь сразу, а не «потом».
- ОКПД2-регулярка может схватить чужое число. Каталог спринта 4 подтверждает код, но не лечит ложное извлечение: finding хранит фрагмент текста.
- Ставка НДС 10% для медицинских изделий — правило таблицы, не константа в коде. Нет строки таблицы — нет утверждения об ошибке ставки.
- Рабочие дни без официального календаря давать нельзя. Пустой example-файл не заполняется выдуманными праздниками.
- П. 4.2.10.2 требует обезличивания, а договор требует настоящие реквизиты. Это два контура, они не смешиваются в одном HTML.
- XML ЕГРЮЛ без реального образца не разбирается частично: полупустая карточка опаснее явного отказа.
- OCR, почта, ЕИС и правовые базы зависят от доступа и лицензий. Их нет в спринтах 1–19 как работающих интеграций.
- Пустая спецификация и «поиск не выполнялся» — разные состояния от «источники проверены, характеристики не извлечены». Первая фраза остаётся, пока клиент не вызывался.
- Неполная локальная спецификация из интернета не дополняется. Поиск запускается только когда спецификации КП нет.
- Текст чужой страницы не исполняется и в журнал целиком не пишется. В отчёт попадает извлечённая строка и адрес, который вернул клиент.
- Найденная карточка реестра не означает допуск товара.
- Дата актуальности не заменяется сегодняшней датой машины.
- Раздел 5 ТЗ пуст, поэтому у спринтов нет дат приёмки заказчиком. Демо спринта — pytest и сценарий Streamlit, не акт сдачи.

## Rollback Plan

- Каждый спринт — отдельный коммит. Откат — `git revert` этого коммита.
- Новые папки `incoming/*` необязательны: пустое отсутствие папки равно пустому списку.
- Новые переменные `KP_*` по умолчанию выключены. Удаление переменной возвращает статус «не проверен».
- Узел графа добавляется в конец цепочки проверки и не заменяет `audit`. Откат узла возвращает прежний отчёт пар. Поиск характеристик узлом графа не является: выключенный флаг возвращает отчёт спринта 15.
- Сгенерированные файлы лежат в `reports/` и в git не коммитятся, если каталог уже в `.gitignore`. Если нет — добавить `reports/contracts/` и `reports/requests/` в `.gitignore` в том же коммите, где появляется запись файлов.
